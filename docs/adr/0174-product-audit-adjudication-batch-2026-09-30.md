## Context

以同套六项产品审计 skill（定位 / 范围 / 目标用户与任务 / 目标与指标 / 特性分诊 / 想法压力测试）
对本仓库重跑审计（HEAD `ae61fc4`），审计仅读仓库，只写 `docs/research/product-audit-2026-09-30/`。
六项独立收敛于同一判断：工程可信、边界清楚，真实需求全为 E/unknown；局部工程事实不构成
真实采用、付费或持续使用价值的证明，当前 HEAD 全量门禁状态在本批中未建立证据。

本轮承接 ADR-0167 决策 6「目标产出先跑需求访谈再定档」，为该前置提供封顶验证的预算与协议，
不提前锁定目标产出。按 AGENTS.md「一切决策问题由用户作答」，本 ADR 记录本批待裁项的裁定
与执行边界，裁定内容依据汇总 §4 合并推荐与 §7 一致性标注；保留证据量尺、新增实验条件、
时间基准与处置对象的区别，不将顶层收敛改写为各项定义完全一致。

## Decision

本批对 9 项逐条裁定（01–06 为 References 所列报告）：

**决策 1 — 对外定位维持执行层主线（01 候选 A）（裁定：维持候选 A——「可信规则执行层：Completeness + 三态 Gate + 签名执行证明取代『0 告警即通过』」；放弃候选 B/C）。**
依据 01 §7，维持定位不等于恢复对外扩建或授予生产权威。

**决策 2 — 投入边界：只批准证据预算，不恢复对外扩建（裁定：暂停一切对外扩建与新增产品面，只批准需求验证的证据预算——最多 21 个日历日 / 研究方 14 小时 / 现金 0 / 新代码 0）。**
依据 04 §2、06 §4.4，预算仅用于需求验证，不授权新增产品能力。

**决策 3 — 需求验证实验 IST-20260930-01 获批（裁定：执行 06 §4 的完整协议；采纳其新增资格与承诺条件（≥4 个组织、每组织 ≤2 人、≥半数非作者熟人、≥2 个不同组织落实自有资源承诺、每人 ≥90 分钟自有工时），批准前冻结、不事后降门槛；翻转/杀死阈值按 06 §4.3）。**
依据 06 §4、02 §6（X4），该等条款是本批新增提案，不得表述为「完全沿用原门槛」。

**决策 4 — 访谈提问顺序采用 06 序，防成功指标自证（裁定：先无提示锁定受访者 top-3，之后才回放 03 的含提示问题；在提示完整性/零告警/SpotBugs 或介绍产品后才出现的痛点不计入无提示 top-3）。**
依据 03 §4、04 §1.2、06 §4.2（X5），不得以提示后的回答回溯抬高无提示痛点证据。

**决策 5 — 证据量尺不合并（裁定：02/03 的局部等级（工程 D / 事件 C / 承诺 B）与 06 的 A–E 各自保留来源原等级与具体事实，不合并成「全体 A/B 证据」，不把某路「承诺 B」自动升为「付费 A」；结论对象另用 §6 的 conclusive / weak / unknown 标注）。**
依据 02 §1、03 §6.1、06 §2.2，结论对象的标注采用汇总 §6，不替换各来源的原始量尺。

**决策 6 — 停止与边界纪律（裁定：达杀死条件（≥5 人用材料否定当前增量价值且 0 个组织落实合格承诺）即停止当前目标群体的独立层扩建论证、不以改门槛 / 加熟人或工程 PASS 补足，保留工程资产与安全维护；支持者若以「先授予生产权威」为前提，按条件性兴趣处理、不冒充已获支持；正式 LIVE_SHADOW 窗口按其原治理条件独立执行，不被本实验覆盖其阈值/窗口/GO 权威）。**
依据 06 §4.3，其余 mixed / unknown 结果保持暂停，不以需求实验替代正式窗口治理。

**决策 7 — 特性处置与用户面（裁定：维持 05 的 Keep 6 / Keep-as-is 52 / Defer 60，Spin-out 0；3 项 Cut（`POST /v1/coverage`、`POST /v1/factory-jobs`、`POST /v1/verification-jobs` 的隐式写入口）批准收撤，执行另立票据、本 ADR 不执行；Defer 主体退出公开文档/首屏，但不删任何运行工具）。**
依据 05 §1.3、§4–§5，叙事降级与 API 入口收撤分别处理，本次仅记录裁定。

**决策 8 — 成功指标（裁定：采纳 04 的北极星——每周独立完成一次可复核完整性判断并选对下一步的合格主用户数（按人去重），及支撑指标 S1–S3、护栏 G1–G6；NS/S1–S3/G2/G6 的埋点/研究账授权建立，数值缺处记「未发现证据」、不填 0）。**
依据 04 §1、§5，指标建立仍受决策 2 的新代码 0 约束，NS 任务完成不等于完整扫描成功，也不得抵消护栏失败。

**决策 9 — 治理人选待用户指定（裁定：研究负责人与复核者的实际人选由用户后续指定（本批未发现证据））。**
依据 03/04/06，不由代理推定研究负责人或复核者人选。

## Consequences

- 对外定位继续聚焦可信规则执行层，Java 本地 / Shadow 主线与必要安全维护保留；对外扩建与新增产品面继续暂停。
- 下一步仅获封顶需求验证授权，新增资格与承诺条件不得事后降低；研究负责人与复核者待用户指定，本 ADR 不执行招募、访谈、埋点或实验。
- 证据保留来源量尺与具体事实，无提示 top-3 先行冻结；缺失数值记「未发现证据」，不将工程 PASS、提示后的痛点或条件性兴趣充当需求支持。
- 达杀死条件即停止当前目标群体的独立层扩建论证，mixed / unknown 继续暂停；正式 LIVE_SHADOW 窗口的阈值、窗口与 GO 权威不变。
- 3 项 Cut 已批准但须另立票据执行，Defer 仅退出公开叙事、不删除运行工具；本 ADR 不修改产品代码、公开文档或既有裁决。
- 目标产出仍待需求访谈与正式窗口证据回填后另行定档，预算授权不等于真实需求已成立，也不追认任何历史指标达标。

## 2026-09-30 补记：裁定出处与门禁实况

**裁定出处**：本 ADR 九条裁定取自 2026-09-30 六镜审计批次的一致推荐（汇总 §4 合并推荐与 §5 待裁项），
依用户在批次后的指示落成，未另行逐条征询；用户对任一条的更正以补充记录覆盖本条。

**门禁实况**：本批审计自身未运行全量门禁（见汇总 §3.5、§8.3）。批次后补跑 `bash scripts/check.sh`
并逐层归因，查得四红，性质与处置各不相同：

1. **仓库侧代码缺陷（已修）** — `control-plane/factory` 的 `CandidateCompilerTest` 两例，在
   `core.autocrlf=true` 的 Windows 检出上失败：测试对 golden fixture 做含 `\n` 的精确字符串替换，
   而该 fixture 在 git 索引为 LF、检出被转为 CRLF，替换静默失配（测试与宿主行尾耦合，非陈旧断言）。
   已外科式修复——在读取处归一化 CRLF→LF，不触产品代码。
2. **仓库侧门禁缺前置（另立票据）** — `scripts/check.sh` 只前置检查 `java`，未检查 `rg` 等硬依赖。
   缺 ripgrep 时，`scripts/check-java-compatibility.sh:20` 首个 `rg -q` 报 127，于 E2E 阶段深处静默中止，
   其后约 46 个阶段一个未跑，且无具名提示。已开票据记录并建议加 external-tool preflight（GitHub Issue #125，`needs-triage`）。
   工具补齐后，门禁自第 4 阶段推进至第 8 阶段。
3. **宿主环境缺陷（不可在仓库侧修复）** — 见下「门禁可执行环境」。
4. **一次假绿** — 由 2 的采集方式导致：以 `wsl.exe … bash -lc '…$?…'` 取退出码时，`$?` 由调用侧
   Windows shell 展开、恒为 0，一度把 `rc=127` 的中止读成全绿。已改为在目标环境内落盘真实退出码。

**关于依赖重钉及其回退**：排查宿主侧红时，曾尝试把仓库 pin 的受治理组合（`pmd 7.9.0` / `jena 5.3.0` /
`spotbugs 4.9.8`，见 ADR-0100）全量重钉至内网镜像所携带的版本，共涉 13 处。**该改动已全部回退**：
受治理组合在 WSL 侧本地仓库完备，所依据的版本缺失只是 Windows 侧镜像的局部现象，不构成改版本的依据。
仓库当前仍为原冻结组合。

**门禁可执行环境**：Windows 检出无法跑通全量门禁，两因均属宿主环境而非仓库代码——(a) 内网 Maven 镜像
`zte-nexus129`（`mirrorOf=*`）对多数构件只同步单一版本，缺 `pmd-java 7.9.0` / `jena-arq 5.3.0` / `spotbugs 4.9.8`
（本地仓库仅剩下载失败标记）；(b) llvm-mingw(UCRT) 缺 libgcc，`x86_64-pc-windows-gnu` 下 cargo 链接报
`unable to find library -lgcc`。故门禁的权威执行环境定为 WSL `kali-linux2` 的原生检出。

**结论**：在 WSL 原生检出上，`bash scripts/check.sh` **51 个阶段全部通过、退出码 0**（含该树当日
在制品阶段；其 `rule-bundle-pack-check` 阶段对 `.scratch` 下陈旧产物非幂等，先清理后可复现全绿）。
须写明两点边界：**(1)** 该绿取自 WSL 原生检出（HEAD `511be3b`），**不含**本 ADR 所审计的 D: 树 HEAD
`ae61fc4`；**D: 树自身 HEAD 的全量门禁未取得全绿证据**，其红已归因为上述宿主环境，仓库侧可归因的红已修复。
**(2)** 受治理 Java 后端组合未因本次排查改动。本 ADR 的裁定不依赖门禁通过。

**文档去向与编号统一**：本 ADR 在两树统一编号为 **0174**（D: 树原为 0173，2026-09-30 当场改齐）。
编号 **0173** 在 WSL 血统已由「确定性多规则 RuleBundle 打包」ADR 占用，故两树合并后
0173 = 该打包 ADR、0174 = 本审计裁定；D: 血统不占 0173，合并时不再撞号。
